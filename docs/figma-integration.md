# 原生设计移植 · v0.2.0 开发记录

用户已明确授权将当前管理页、浮窗、Logo 和菜单栏图标移植到原生代码，并打开应用供点击。授权记录集中在 [prototype.md](prototype.md)。当前已接入源码、打包签名并通过内容与完整原生 UI 回归；采用系统字体、真实统计数据及用户追加的原生窗口按钮，不声称不同字体渲染逐像素相同。

## 实现范围

- 菜单栏提供管理内容和使用统计入口；采用已制作的单色模板图标，应用包包含正式应用图标。
- 管理窗口包括分类、标题／简述搜索、列表、Prompt 预览、完整复制、原文来源查看，以及新增／编辑表单。根据用户试用反馈加入原生红黄绿按钮，支持关闭、最小化和放大；关闭前保存草稿。保存后通知浮窗刷新；稳定 ID 与原始字段不变。
- 浮窗保留三级、全局快捷键、缩放和既有插入校验。按最新稿移除目标应用标签及分类色点，分类文字带柔光；详情分为 Prompt 与经验／来源，正文仍可选择。
- 统计来自当前版本明确成功的复制、插入动作。插入过程内部使用剪贴板不额外计为复制；普通文本选择复制不算完整 Prompt 调用。历史数据不凭空补录，初始可为零。
- 无账号、LLM、后端或云端同步；未扩展到删除、导入导出和浮窗搜索。

## 数据与回滚

正式内容仍用 schema v1 的 library.sqlite3，新增／编辑在事务内提交，编辑检查原版本，失败保留表单。重试使用同一个 ID，避免重复新增。分类数量为元数据 COUNT，不读取标题或正文；原有列表查询仍只返回标题和简述。

草稿与使用事件存于同目录的 library-activity.sqlite3，通过当前串行 repository 连接附加访问。它是独立 SQLite 文件，不在正式内容库中增加表或提升 user_version；旧只读版本仍可读取内容主库。退出前完成待写入和草稿保存，避免结束进程时丢弃后台任务。

本轮已在启动新版本前使用 SQLite backup API 备份现有内容主库，备份保存在本机 Application Support/Prompt Injector/Backups。代码回滚不恢复已经编辑的数据；恢复数据库之前先退出所有应用版本并保留当前数据的另一份备份。不要删除伴随库来“回滚”草稿或统计。
