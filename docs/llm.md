# v0.3 · DeepSeek 整理与可扩展分类

2026-11-01 用户确认使用 **DeepSeek V4.1 Flash 1017**。客户端调用名为 `deepseek-flash`，官方文档当前将它映射到该版本；该别名今后可能由供应商升级。地址固定为 `https://api.deepseek.com/chat/completions`，开启 `thinking: enabled` 与 `reasoning_effort: high`。不增加模型/地址配置、工具调用、中转服务器或网页抓取。

接口依据：[模型与别名](https://api-docs.deepseek.com/quick_start/pricing/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。这些是实现依据，不代表本机已经完成真实 API 验收。

## 使用

1. 管理内容 → 加号新增。在“原始经验与解释”粘贴原文，按需填写来源（作者、出处或链接）。输入自动保存为本地草稿。
2. 编辑页左下钥匙按钮配置 API key。安全输入框保存到本机 Keychain，不写 SQLite、UserDefaults、代码、Git 或诊断日志；重新配置只更新同一个 Keychain 项。取消输入不修改已存 key。
3. 点击“整理”。App 先确认这次输入已持久化，再读取当前分类并异步请求 API。等待期间可继续编辑，也可点击“取消整理”；修改输入会取消当前整理，以免旧结果覆盖后来内容。
4. 在“整理候选”直接审核、编辑完整字段和分类，候选修改也保存为草稿。点击“采用候选”才替换标题、简述、解释、Prompt 和分类；原文和来源保持原样。可继续编辑，再保存。已有候选时，重新整理先确认是否替换候选及其修改；失败仍保留旧候选，不自动填入编辑稿。
5. 分类菜单可选择数据库现有分类，或“新增分类…”后在同页填写名称。模型建议新分类时同样可修改名称。保存时才创建分类，并与条目同事务提交。空白、控制字符和超过 80 字的名称会被拒绝；首尾空白、Unicode 规范等价、大小写与全半角等价名称做基本去重。
6. 保存成功后管理页、浮窗和统计刷新。新分类按数据库顺序循环现有五色与柔光圆点，使用 `folder` 符号；已有五类保持原 ID、颜色、排序和关联。

整理会把本次原始经验、来源和当前分类 ID/名称发送给 DeepSeek，只有点击整理才请求。已有内容浏览、搜索、复制、插入和统计全在本地。API 按供应商账户计费，本轮未创建账号、充值或付费资源。

## 提示词与结构

完整系统提示词以 `macOS/PromptInjector/Services/DeepSeekClient.swift` 的 `systemPrompt` 为唯一实现来源，可以直接审阅修改。它要求标题简短（中文通常 8–12 字）、简述只写一句适用条件；只依据原文，保留条件与例外，不增加无依据的要求、步骤、工具或事实，不虚构作者/链接，把用户输入当作数据，返回 JSON。

模型收到两条消息：system 提示词；user 为以下独立 JSON 数据（字符串由 JSON 编码器转义，不拼接为指令）：

```json
{"originalExperience":"粘贴的原文","source":"用户填写的来源","categories":[{"id":"coding","name":"编码"}]}
```

工具列表为空，模型没有访问 SQLite、Keychain、文件、网页或目标输入框的能力。返回只允许六个键：

```json
{"title":"用途标题","summary":"适用场景","explanation":"方法、理由与条件","prompt":"明确指令","categoryID":"coding","newCategoryName":null}
```

新分类则 `categoryID: null`、`newCategoryName: "新名称"`。两项恰好一个为非空字符串；已有 ID 必须来自本次请求分类快照。每次整理前重新查询 SQLite，不缓存启动时的分类。按主要用途优先复用，近义词、工具名或细分主题不单独新建；模型误报的同名新类在本地转换为已有 ID。语义相近仍需人工确认，不自动合并分类。不允许模型返回原文或来源字段。

供应商 JSON 模式保证不了业务字段，因此客户端再次校验键集合、类型、必填、长度、分类互斥和 ID。拒绝空白内容、未知分类、错误/截断 finish_reason、无效 JSON、额外字段和多结果。来源保真由本地编辑器实现；语义忠实度仍需用户审核，字段校验不能证明模型理解正确。

## 失败与数据边界

- URLSession 使用无磁盘缓存/凭证缓存的 ephemeral session，拒绝重定向；Keychain 访问、编码、网络和解析均离开主线程。单次总网络期限 180 秒，最多 32768 输出 token（包括供应商计入的思考），达到限制的截断结果不会采用。不静默重试，避免重复计费。
- 原文限 60,000 字，来源限 10,000 字，整个输入 JSON 限 400 KB；候选四字段各有长度上限。超限明确失败，原稿保留。
- API key 缺失、认证失败、余额不足、限流、网络中断、超时和无效结果分别反馈。日志只有固定阶段、operationID、状态/错误码，不记录 key、正文、来源、响应体或思考过程。
- 请求绑定 operationID、编辑器实例与草稿快照。取消、编辑、切页、保存、关闭或退出都会使它失效；即使供应商迟到返回也不能存入后来编辑器。旧候选及其手改在失败/重试时仍保留；成功重新生成会替换候选，不替换采用后的编辑稿。关闭前保存当前草稿和候选，退出前排空 SQLite 队列。
- 内容库仍是 schema v1；伴随库的草稿 JSON 增加可选 `newCategoryName` / `candidate`，旧草稿可解码。新增分类与条目、草稿清除共用一个事务；失败时一起回滚，不留下空分类。

## 回滚与恢复

代码：撤销本轮普通提交（或在独立 worktree 检出改动前基线），运行完整套件后再按授权使用旧包。主库未改 schema，已生成内容、新分类与使用事件仍在，代码回滚不会撤销它们。旧 v0.2 的管理/分类/统计仍含五类假设，含新分类使用事件时统计可能报错；不要把 schema v1 可读等同于旧 UI 完全兼容。需要保留新分类和历史，应继续使用支持动态分类的读取代码。

数据：退出所有应用实例后，备份并成对恢复 `~/Library/Application Support/Prompt Injector/library.sqlite3` 与 `library-activity.sqlite3`（或整个目录，含可能存在的 SQLite 日志文件）。恢复前再备份当前状态。恢复旧快照会失去快照之后的有效编辑；不要删伴随库或改 user_version 来模拟回滚。产品导入导出仍未实现，测试里的 JSON 往返仅验证字段保真。

凭证独立存在 Keychain，Git 回滚和 SQLite 恢复均不会恢复或删除它。需要撤销可在 Keychain Access 删除 service `com.promptinjector.deepseek` / account `api-key` 项，或在 DeepSeek 控制台撤销原 key。

## 本轮 20 条实验补充

用户明确要求把粘贴的 20 条经验整理并保存本地，授权这一批正式写入。维护者实验入口 `--experiment-experiences <input.json> <输出目录>` 用当前分类逐条调用真实 API，每条保留稳定 UUID 和原文/来源；未采用全局抓取或执行生成内容。失败项保留输入与候选，重新运行不覆盖已存在 ID。`--apply-experiment-review <reviewed.json>` 仅按完整旧快照保存经审核的文本，检查 ID、原文和来源不变。这两个维护入口都只在显式调用时执行，不是产品导入导出 UI，也不随常规回归调用付费 API。正式库未完成的其他草稿不会被本批保存清除（PI-018）。

本批审核发现并修剪：原文没有的等待批准门槛、条件/建议变强制、虚构日志输入字段。systemPrompt 已追加保持语气强度与不新增确认门槛的约束；对第 9 条再次真实请求验证改进。LLM 字段校验通过仍不意味着语义忠实。详细结果可在本机 `artifacts/experiments/tw93-2115366100221501540/experiment.md` 查看。
