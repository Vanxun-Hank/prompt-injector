# 内容管理 V2 · 扫读与分层阅读

状态：2026-11-01，用户要求先在 Figma 网页版调整内容管理，以当前 v0.3 App 为基准；用户随后确认移植，当前已接入 AppKit。原 V1 保留。实现授权与审核结果只在 prototype.md 维护。

模式：Operate。沿用当前深色原生窗口、Logo、系统窗口按钮、分类侧栏、搜索、复制和编辑，不另换视觉风格。

## 信息层级

- 标题说明用途或动作，目标为 8–12 个汉字或相近显示长度；去掉“让 Agent 为项目……”等长前缀。副标题只补一句使用时机或必要条件，不承担解释、不重复标题。
- 示例：标题「用脚本验证规则」，副标题「有硬性规则时使用」。当前 Figma 示意文案已精简；App 中既有条目、草稿和来源未改写。
- 列表只显示标题和一行简述，移除每行重复的分类／来源文字。分类仍在侧栏与当前详情中保留；窄列随宽度伸缩，不能直接裁掉文字。
- 详情每次只阅读一类内容：「Prompt / 作者原文 / 整理说明」。默认 Prompt 不常驻长解释；点击作者原文后独立显示作者分享的原字句与来源链接，不把解释和原文接在 Prompt 末尾。
- Prompt 使用 16 pt 常规字重、32 pt 行高，必要关键词中等字重；正文最大阅读宽度 640 pt。标题 22 pt，简述 13 pt；解释只在独立分页里阅读。
- 页头将标题、搜索和加号放在一行，释放正文高度；复制和编辑继续使用固定的 40 pt 图标按钮。保留当前主导航与原生窗口行为。

## 分类颜色

用户明确要求以现有五色为基础，按 SQLite 分类顺序循环：黄、蓝、珊瑚、紫、粉。第六类「模型选择」用黄，第七类「Agent 指令文档维护」用蓝。名称和色点使用同一颜色；颜色不能作为分类唯一标识。

这项决定替代此前“新分类统一白色”的方案。侧栏、编辑选择、详情、浮窗和统计共用同一实际分类顺序；不增加数据库颜色字段。

## 本轮画面与验证

已制作 1440 × 960 的 Prompt、作者原文、整理说明三种状态，以及 1100 × 720 最小窗口。默认三种阅读状态有原型连线；最小窗口用于静态排版核对。

所有界面由可编辑文字、组件实例与向量组成，复用原文件 Logo 和图标，没有把整张 UI 截图塞回画布。Figma 中文延续 Noto Sans SC，英文品牌与数字沿用 Inter；客户端仍用原生系统字体。

Figma MCP 完成编辑与结构回读。截图接口超时后，改用 Figma 网页版原生导出 1× PNG；本机证据位于 artifacts/reading-v2/。已核对分类循环色、窄列伸缩、短标题／副标题及原文独立阅读；独立 finish review 对四张设计导出判定 ship；另在网页原型中实际点击验证 Prompt → 作者原文 → 整理说明 → Prompt。此结论仅覆盖 Figma 设计与这三态原型，不替代原生交互验收。

AppKit 已采用紧凑页头、80 pt 双行列表、三页独立阅读与固定复制／编辑按钮；保留系统字体、正文选择、来源链接和完整 Prompt 复制。既有标题／简述不批量重写，长文字最多两行预览并提供完整 tooltip，编辑器保留全文。分类区域独立滚动；主导航和底部快捷键固定。

## 分类上下文与模型约束

每次点击整理，在原文草稿落盘后，通过 PromptLibrary 后台队列重新查询 SQLite 分类，发送完整 ID／名称列表；新增分类提交后，下一次生成立即包含它。无需额外工具、服务、配置开关或自动合并。

systemPrompt 要求按主要用途逐项匹配；同义名称、不同工具与同一用途的细分主题优先复用已有 ID，仅所有分类都不合适时才建议新名称。同名建议在本地校验后转换成已有 ID（空白、大小写、全半角归一），保存事务仍做最终去重。语义判断仍可能出错，新名称需人工确认，不以相似度自动迁移条目或历史。

标题指导改为中文通常 8–12 字、简述只给一句使用条件，影响后续生成；本地安全长度上限不阻止已有内容编辑。完整提示词见 DeepSeekClient.swift，工具列表仍为空。

自动化、真实 API、原生画面与未测边界见 testing.md；不将 Figma 原型或模拟目标当作真实 Codex 插入。
