# 界面演进与当前基线

## 当前实现授权 · 2026-10-30

用户已明确要求将当前 Figma 管理页、浮窗、Logo 与菜单栏图标移植到原生代码并打开供点击，授权本轮客户端实现。范围包含管理页的手动新增、编辑、标题／简述搜索和本地使用统计；沿用本地 SQLite、只填写不发送及既有系统插入保护，不引入云端、账号或 LLM。以本轮实际构建与运行结果更新完成状态，不再重复索要相同实现批准。

用户试用后明确追加：管理窗口需有原生 macOS 红黄绿按钮，支持关闭、最小化和放大。此反馈优先于 Figma 无标题栏的外壳形式；内容布局保持当前方向，关闭仍须先保存草稿。

用户随后要求预览分类色点与文字对齐，或去点只留名称，并放大分类名称；本轮采用去掉预览色点、14 pt 中等字重且与标题左对齐。另明确要求全界面移除无用说明：重复示例来源、本地存储／浮窗调用旁白、编辑格式与作者提示、统计口径说明等常驻文字不再显示。实际原文、来源与解释字段保留，必要标签、状态、错误和快捷键保留。

用户还要求绿色按钮进入独立桌面空间的原生全屏，并使用自己的 Logo 作为应用图标。管理窗口增加主全屏资格，显示时切换正式应用身份并设置品牌图标；原生全屏进出已检查，真实应用绿色按钮点击亦产生 fullscreen-entered 事件。此授权针对当前 macOS 客户端管理窗口，不新增服务器界面或后端功能。

当前开发版已将最新 Figma 管理页、浮窗与图标接入 Swift/AppKit，功能和数据验证见 [figma-integration.md](figma-integration.md)。新版内容与完整原生 UI 回归已通过；历史 Stage 1 插入验收不自动等于本轮重新测试。早期浅色设计方案已否决，不作为后续开发依据；不需要重新等待旧原型的审批。

当前方向为中性深色面板、白色通用控件、渐变柔光 Logo 与分类语义色。设计规则见 [DESIGN.md](../DESIGN.md)，布局和交互约定见 [launcher-brief.md](launcher-brief.md)。私人参考截图、对话和早期设计文件链接不公开。

## 重要演进

- 单浮窗三级导航；标题与简述保留，长正文可滚动，导航和底部操作固定。
- 清除右上角重复应用名称，统一返回箭头、标题、行内容和详情左侧对齐。
- 使用 NSVisualEffectView 与背景遮罩实现磨砂，不用整个窗口透明度模拟静态材质。
- 增加短促的窗口显示/隐藏及页面前进/返回动画；支持快速中断和减少动态效果。
- 先通过真实 Codex 插入，再加入 SQLite 分层读取；数据层变更保留现有视觉和插入约束。
- 锁屏曾使截图与动画时序检查失败；解锁后同构建通过。测试环境必须记录，不把旧截图当作本轮新结果。

## 内容管理视觉参考 · 2026-10-30

用户明确允许参考 Web 产品风格，并指定 Ponytail 的 [The Band](https://github.com/DietrichGebert/ponytail/blob/main/assets/band/band.png) 和 [Board / dashboard](https://github.com/DietrichGebert/ponytail/blob/main/assets/band/board.png)。两张公开原图均已查看，作为内容管理下一轮设计的主要视觉参考。

- Board：深黑背景、略亮的炭灰面板、低对比细边界、柔和圆角；清楚的侧栏与内容区，白色主文字和灰色辅助文字，少量彩色标记。
- Band：紧凑横向操作条、分组与细分隔线；操作与状态清楚区分。按用户最新截图校正，管理草稿中的选中项和主要操作使用深灰底、白色文字与图标，辅助数量为灰色。
- 将这些视觉语言用于分类、标题与简述列表、独立内容编辑区。原始经验、来源、解释与 Prompt 继续分开保存和呈现，Prompt 保留足够的编辑空间。
- 用户随后明确追加 Prompt 使用次数统计与排行，纳入 Figma 草稿。统计页借鉴 Board 的指标、趋势与表格组织；Figma 数据为演示。当前开发版已接入真实成功复制／插入事件与本地持久化，不使用演示历史。参考图中的费用与 token 不成为本项目需求。
- 用户先指出分类容易误触，随后明确要求去掉分类外框、选中项改为深灰底和彩色字体、分类色点带柔光。保留 44 高整行点击区和 10 行间距，主导航与分类之间保留分隔线，不采用逐行描边；已接入原生控件并完成画面对照。
- 用户进一步要求 Logo 发亮、所有分类色点都发亮：四个管理画面中的 Logo 增加同形渐变柔光，全部分类色点统一提亮，包括侧栏、预览、编辑选择和统计图例／分布；状态提示圆点继续按状态含义呈现。
- 用户随后纠正通用控制泛用蓝色的问题：全部内容、使用统计、新建／编辑／保存及重试操作、选中页签和统计时段统一采用白色文字与图标；数量与边界回归中性灰。此前彩色文字要求仅保留在分类语义，Logo、发光分类色点和统计系列保留原配色。
- 用户要求内容预览右下角的复制与编辑仅显示图标，两者统一沿用复制按钮样式：透明背景、细灰边框、白色图标，均为 40 × 40；原生实现已提供 tooltip 和辅助功能名称，并完成画面对照。

状态：用户已确认“内容管理可以了”。内容管理静态视觉方向通过，含无框分类、深灰选中态、白色通用操作、分类彩色文字、柔光色点和统一图标按钮。此确认不代表客户端实现或统计采集已获验收。
