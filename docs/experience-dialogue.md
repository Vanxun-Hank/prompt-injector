# v0.4.0 · 经验讨论与批量整理

原生 AppKit 已接入 V5 双栏：左侧讨论，右侧识别出的经验；单条与多条共用同一数据流。仍由 Swift 客户端直连 DeepSeek，Keychain 保存现有 key，SQLite 保存内容与草稿，没有新增中转服务器、账号或模型配置。

## 使用与数据流

1. 管理页加号进入会话。粘贴正文，或发送公开 HTTP/HTTPS 链接；来源可另填。输入先经后台队列持久化，再调用 API。已有手工编辑草稿继续在原编辑器恢复，避免迁移丢失手改字段；完成旧草稿后，加号使用新会话。
2. 链接通过 DeepSeek Fetch 取正文，失败提示粘贴继续。成功取文先落盘，识别失败后重试复用该正文；修改初始输入会使旧正文缓存失效。X 的已知单行 Fetch 格式只有在标题完整重复主帖、引号边界明确且正文无续行时才移除重复标题和回复；多行／未知格式完整保留，再由模型识别，仍需检查结果是否属于主体作者。
3. 识别返回短标题与逐字原句。客户端拒绝未知键、空结果、重复片段、改写片段和不在原文中的引用；为每条分配稳定 UUID。整篇原文与来源单独保存，讨论与候选不回写这些字段。
4. 点经验文字发起该条开场讨论，保留该条未发送输入；再次进入已有讨论时继续历史。方框只切换勾选，不发请求。每轮回复后有分隔线，两列独立滚动，输入框与整理操作固定。每条聊天和输入独立保存；新回复只落到匹配的条目／请求，不覆盖后续输入。
5. 「整理已勾选」逐条请求候选。每次请求前读完整数据库分类；传入当前条讨论与完整原文背景，保留文章开头的全局条件。优先复用已有 ID，新分类只建议名称。纯概念澄清放解释，用户明确采纳的执行要求可进入 Prompt；讨论补充与原文方法分开。已有有效候选直接进入审核；讨论变化需重新生成时先确认替换，失败保留旧候选与手改，成功条目不因另一条失败而重新计费请求。
6. 审核页复用原编辑器，逐条切换、修改标题／简述／解释／Prompt／分类。作者原文与来源只读，来源显示 X、GitHub、Reddit 本地矢量标识，未知平台用通用链接标识。用户确认后，分类去重、全部选定条目、草稿更新和会话存档同事务提交；失败全部回滚，不留下半批条目或空分类。
7. 保存成功才通知管理页与浮窗刷新。未选条目的聊天、输入与候选留在草稿；已保存批次的完整原文与讨论留在伴随库存档。既有浏览、搜索、完整复制、插入与统计继续本地运行。

## 网络、提示词与工具边界

调用顺序由 App 控制：`/v1/tools/fetch`（仅输入链接时）、识别 JSON、普通文本多轮讨论、整理 JSON。模型仍为 `deepseek-flash`，启用 high 思考，单请求期限 180 秒；不自动重试。API 取文可能受站点策略限制，Fetch 单独按成功请求计费，见 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/search/)。日常回归不发付费请求。

完整提示词和请求编码以 [DeepSeekClient.swift](../macOS/PromptInjector/Services/DeepSeekClient.swift) 为准：`identifyPrompt` 仅识别主体作者经验并返回准确引用；`discussionPrompt` 解释当前条的概念和条件；`organize` 复用 `systemPrompt`，追加讨论补充、用户采纳和完整原文条件规则。输入均经 JSON 编码，不拼进系统指令。

每次讨论传本条原句、整篇原文背景、来源和本条消息；不混入其他条目的聊天。整理再附最新分类 ID／名称。模型没有文件、Shell、SQLite、Keychain 或系统插入工具，不能勾选、写库或操作电脑；Fetch 是 App 直接调用的读取接口。

聊天当前等待整条回复后显示，不逐字流式显示；等待时可继续输入、取消或切换条目。每条最多 500 条消息，发送前预留用户与回复位置，达到限制保留输入和可保存草稿。原文最多 60,000 字、来源最多 10,000 字、每次编码请求最多 1 MB，超过限制明确失败，不静默截断正文或聊天。

## 持久化、删除与回滚

正式 `library.sqlite3` 继续 schema v1，五个种子分类及 ID 不改。分类颜色由完整数据库顺序取十五色循环，第 16 类回到第 1 色；管理、编辑、浮窗和统计共用映射，不存颜色配置、不自动合并语义相近分类。

伴随 `library-activity.sqlite3` 新增 `experience_drafts` 与 `experience_archives`，不替换旧 `editor_drafts`、`usage_events`。会话有版本号；存档版本阻止旧自动保存复活已提交批次。请求前落盘，关闭／退出先使网络请求失效，保存当前输入并排空队列。异常中断留下的 pending 消息在恢复时标为可重试，同时推进草稿版本。

删除需点名确认，只移除该 Prompt，保留分类和历史使用快照。提交后失效旧详情，不能再插入已删缓存。取消、事务失败或过期快照不删除；没有回收站／产品导入导出入口。

代码回滚：退出当前包，恢复更新前已备份的 v0.3.1 `.app`；或在独立 worktree 检出旧基线 `9311546` 后构建。不要用重置覆盖当前工作区的未提交修改。旧包仍可读正式条目与动态分类，但不显示新会话，新表应保留以便再次升级恢复。代码回滚不会恢复删除内容或撤销用户编辑。

数据恢复：先正常退出所有实例、再备份当前状态，成对恢复 `library.sqlite3` 和 `library-activity.sqlite3`。本轮更新前备份目录记录在本机 `artifacts/installation/v040/backup.json`；旧包与两库一起保存。恢复旧快照会舍弃快照之后的有效改动，不能靠删伴随库或修改 user_version 模拟回滚。Keychain 独立存在，代码／两库恢复均不改变凭证。

## 自行验证

在仓库根目录运行，Python 3 标准库，无新增依赖：

```sh
python3 scripts/verify-experience.py
```

该脚本调用 `python3 scripts/test-suite.py`，运行 Swift、Python、独立签名构建与真实 AppKit 窗口检查，保留机器可读报告与截图；默认输出 `build/Experience-Review/Prompt Injector.app`，不覆盖常用安装包，测试数据库完全隔离。新增检查覆盖实际加号、发送、讨论文字与方框点击、逐轮分隔、最小窗口、原文只读、候选手改、批量保存、浮窗立即加载与取消／确认删除。

锁屏或无桌面只能先跑部分检查：

```sh
python3 scripts/verify-experience.py --headless
```

明确开启真实调用，使用现有 Keychain key；每次会产生 API 费用，不自动充值或创建资源：

```sh
python3 scripts/verify-experience.py --live-api
python3 scripts/verify-experience.py --live-api --source-url https://x.com/HiTw93/status/2115366100221501540
```

第一条用两条公开固定经验；第二条实际 Fetch／识别该链接，选前两条验证多轮讨论、整理、修改候选、临时 SQLite 保存与重开，其余经验保留在隔离草稿。`artifacts/experience-verification/<UTC时间>/report.json` 明确区分模拟套件、真实 API、取文和正式库是否改变，失败返回非零；截图与完整套件报告另存 `artifacts/tests/`。更换模型／提示词后可重跑相同案例。

当前测试入口：`ExperienceTests`（事务、去重、旧记录／重开、取消重试、迟到、首聊输入、消息上限、多行来源）、`DeepSeekClientTests`（HTTP、完整上下文、结构、失败与来源边界）、原生 `experience/*`。字段校验与模拟响应不能证明所有模型输出语义正确。真实 Codex 跨应用插入、物理断网、真实系统权限缺失及目标失效仍须单独人工验收；插入保护与不自动发送逻辑未改。
